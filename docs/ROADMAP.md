# 開發順序

決策背景（2026-09 討論結論）：

- 交易所：**Binance**（U 本位永續）
- 主時間框架：**日內 1H–4H**，1D 定方向、4H 定結構、15m 找進場
- 合約本金：**$44 量級**，單筆風險目標 1%（但受最小下單量限制，實際做不到，見下）
- 介面：**完整中文教學模式**

## 第一階段：風險計算 ✅

`index.html` + `assets/risk.js`

核心發現（已寫進測試）：

- $44 / 20x / 進場 80,606 的多單 → 爆倉價 **$76,883**，距離 **−4.61%**
- 價格每動 1%，帳戶動 20%；**−2.5% 帳戶腰斬**
- BTCUSDT 最小下單 0.001 BTC，但名目不得低於 100 USDT。
  在 80,606 的價格下 0.001 BTC 只有 $80.6 → **被迫跳到 0.002 BTC（$161）**
- 因此用 $44 開最小倉，槓桿下限是 **3.66 倍**，配 2% 止損的最小風險是帳戶的 **7.3%**
- **1% 單筆風險在這個本金規模下物理上做不到** —— 這不是紀律問題

## 第二階段：行情與訊號

- `assets/data.js`：Binance 公開端點封裝
  - `/fapi/v1/klines`、`/fapi/v1/premiumIndex`（資金費率）、`/futures/data/openInterestHist`
  - `/fapi/v1/exchangeInfo` → 用真實的 minQty / stepSize / minNotional 取代寫死的預設值
  - `/fapi/v1/leverageBracket` → 真實的維持保證金率（目前用 0.4% 預設）
- `assets/indicators.js`：EMA 20/50/200、RSI14、MACD、ATR14、布林、成交量
- 多時間框架對齊：三個框架不同調 → 直接標「觀望」。**「不做」的訊號和「做」一樣重要**
- 進場計畫卡：方向／進場區間／止損／TP1 TP2（R 倍數）／部位大小／爆倉價／可行性

離線處理：API 抓不到時要有明確的錯誤提示 + 手動貼上資料的備援，不要讓頁面空白。

## 第三階段：交易日誌

每筆記錄：日期、方向、進場、止損、出場、實際 R 倍數、當時的訊號依據。
累積輸出：勝率、平均 R、期望值、最大連續虧損、最大回撤。

**做滿 30 筆才知道自己的流程行不行。這個答案比任何指標訊號都值錢。**
資料存 localStorage（要 try/catch，私密視窗會丟例外），並提供 JSON 匯出。

## 第四階段：幣種篩選器

掃永續合約成交量前 50–100 名，排出偏多／偏空清單。評分維度：

- 相對 BTC 的強弱（BTC 漲它不漲 = 弱）
- 日線與 4H 的趨勢一致性
- 動能位置（RSI 極端、背離）
- 資金費率（極端正值 = 多單擁擠，**當反指標**，不是順向訊號）
- 流動性門檻（成交量太低直接剔除）

⚠️ 山寨幣合約流動性薄、針多。介面上要明確標示這點，
初期建議只當觀察用，實單先在 BTC/ETH 練。

## 第五階段：回測

用過去 1–2 年 K 線跑第二階段的訊號邏輯，輸出勝率、盈虧比、最大回撤、期望值。
**手續費和資金費必須算進去** —— 不然結果會好看得不真實。

沒有回測數字的指標就是玄學：看起來很準，是因為只記得準的那幾次。
