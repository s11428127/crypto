# 開發紀錄

決策背景：

- 交易所 **Binance**（U 本位永續），備援 Bybit
- 主時間框架 **日內 1H–4H**：1D 定方向 → 4H 定結構 → 15m 定時機
- 合約本金 **$44 量級**，目標是把流程練到可以放大
- 介面 **純操作**，不要教學文字

全部五個階段都已完成。以下是踩過的坑，別再犯。

## 各階段成果

1. **風險計算** — 爆倉價、從止損反推部位、交易所最小下單量的可行性檢查
2. **即時行情與訊號** — 公開端點 + WebSocket、K 線圖、多框架對齊、進場計畫卡
3. **交易日誌** — 每筆的 R 倍數、真實勝率與期望值、可匯出
4. **幣種篩選器** — 趨勢一致性／相對 BTC 強弱／RSI／資金費率評分
5. **模擬與回測** — 蒙地卡羅結果分布 + 真實歷史 K 線回測

## 踩過的坑

**`isFinite(null) === true`**（`Number(null)` 是 0）
讓「有值就用、沒值就備援」的三元判斷選中 null，價格顯示與 K 線圖整個拋例外。
一律用 `isNum(x) = typeof x === 'number' && isFinite(x)`。

**趨勢判讀不能只看「收盤在均線上方」**
均線糾結的橫盤會被誤判成趨勢。已加 ATR 門檻：均線要發散 0.3 ATR 以上才算方向。

**進場價必須用即時價**
4H 收盤可能是 4 小時前的價格，拿它算進場區間會整段偏掉。
優先序：WebSocket > 24h ticker > 最短週期收盤。已加 E2E 斷言鎖住。

**回測的日線不能用 4H 併**
1500 根 4H 併出來只有 250 天，連日線 EMA200 都湊不齊，結果是一筆交易都開不出來。
日線要向交易所單獨抓（1000 根 ≈ 3 年）。

**回測偷看未來的三個入口**
① 樞紐高低點需要右側確認 → 最新可用的在 i−lb
② 進場價要用下一根開盤，不是當根收盤
③ 同一根同時觸及止損與止盈 → 算止損（保守）

**RSI 的參考值要查證**
我一開始憑記憶寫 70.53，實際手算是 70.4641。指標一定要對照外部公認的序列驗算。

## 還沒做 / 已知限制

- **維持保證金率仍用 0.4% 預設。** `/fapi/v1/leverageBracket` 需要簽章，
  公開端點拿不到，所以爆倉價和交易所 App 會有小誤差（頁面上已標註）。
- 回測不模擬 15m 的時機過濾、不模擬滑點與部分成交。
- 回測的資金費用固定平均值估算，不是歷史實際費率。
- 篩選器一次掃 30~50 個幣要發 60~100 個請求，可能觸發交易所限流。
  已限制並行數為 4，但沒有做退避重試。
