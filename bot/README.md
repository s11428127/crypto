# 模擬單機器人

用**真實行情**跑模擬單，累積一份可以檢驗的成績單。

**不下真實訂單、不需要 API 金鑰、碰不到任何帳戶。**

## 為什麼先做模擬單

你想知道的是「這套邏輯會不會賺錢」。那個問題不需要拿真錢去問。

模擬單用真實價格、真實手續費、真實資金費記錄每一筆，
做滿 30 筆之後的勝率與期望值，就是這套規則的體檢報告。
**如果連模擬單都不賺錢，真實下單只會更差**（還多了滑點和你自己的手抖）。

## 怎麼打開

排程已經寫好了（`.github/workflows/paper-bot.yml`，每小時跑一輪）。要讓它動起來：

1. **開啟 Actions 的寫入權限**
   repo → Settings → Actions → General → Workflow permissions
   → 選 **Read and write permissions** → Save
   （機器人要把狀態寫回 `bot/state.json`，沒有這個權限會推不上去）

2. **手動跑第一輪**
   repo → Actions → 左邊選「模擬單機器人」→ Run workflow

3. 之後每小時會自己跑。成績在 `bot/state.json`，
   或用 `bot.html` 那一頁看圖表。

> GitHub 的 `schedule` 只會在**預設分支**上觸發。
> 如果之後改了預設分支，記得把這個 workflow 一起搬過去。

## 本機跑

```bash
npm run bot:dry     # 跑一輪但不寫檔
npm run bot         # 跑一輪並更新 bot/state.json
node bot/run.mjs --reset   # 砍掉重練（會先備份舊狀態）
```

## 設定

`bot/config.json`：

| 欄位 | 意思 |
|---|---|
| `startEquity` | 起始本金（只有第一次建檔時有用，之後改它不會動到已累積的權益） |
| `riskPct` | 單筆願意虧掉本金的幾 % |
| `maxLeverage` | 槓桿上限，超過就不開這筆 |
| `feeRate` | 單邊吃單費率 |
| `fundingPer8h` | 抓不到即時資金費率時的估計值 |
| `filters` | **實際會下單的交易所**的下單限制，不是行情來源的 |

## 資料來源

依序嘗試 **Binance → Bybit → Kraken**，第一個成功的就用。

Kraken 那一層是為了排程而存在的：GitHub Actions 的機器在美國，
Binance / Bybit / OKX 都封鎖美國 IP，Kraken 沒有。
代價是 Kraken 是**現貨**資料，沒有資金費率（會退回 `config.fundingPer8h` 的估計值），
歷史也只有 720 根。價格走勢和永續幾乎一樣，跑訊號沒問題。

## 規則

和主控台的進場計畫卡完全一樣：

- **1D 定方向、4H 定結構、15m 定時機**，三者不同調就空手
- 止損放 4H 結構外面加 0.25 ATR，夾在 0.8～2.5 ATR 之間
- 止盈 TP1 = 1.5R（單一目標，全出）
- 部位大小由「風險% ÷ 止損距離%」反推，捨去到最小跳動單位
- 開不起來（超過槓桿上限、爆倉價落在止損之內）就不做

## 刻意保守的地方

寧可低估績效，也不要做出一份好看但騙人的成績單：

- 進出場都算**吃單**手續費，不假設掛單成交
- 止損／止盈用**期間內的最高最低價**判斷，不是只看當下報價
  （只看當下會漏掉「掃到止損又彈回去」，那會讓績效虛高）
- 同一根同時觸及止損與止盈 → **算止損**
- 同時只持有一個部位

## 模擬單和真實交易的差距

即使模擬單賺錢，真實下單還是會比它差：

- **滑點** —— 市價單不會剛好成交在你看到的價格
- **部分成交** —— 流動性不足時單子可能只成交一部分
- **你自己** —— 看到浮虧會手癢提前平倉，看到浮盈會想凹更多

所以模擬單的成績是**上限**，不是預期值。
